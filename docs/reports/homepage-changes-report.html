02 Why these three tests

The homepage already had strong coverage (nav, subscription, Recommended Items add-to-cart). Three real gaps remained:

Features Items add-to-cart had zero coverage. It looks similar to Recommended Items but is a separate grid, a separate CSS scope, and the primary product-discovery surface on the page — the first thing most visitors see.
"Continue Shopping" was not automated anywhere in the repository — confirmed by a repo-wide search that found only a docstring comment, no executable test. Every existing add-to-cart test only exercises the "View Cart" branch of the confirmation modal.
Broken product images — raised directly by the reviewer: a broken product photo undermines trust and can cost sales, and nothing checked for it anywhere in the suite. Added as a DOM-level check, not a screenshot diff, so it survives legitimate visual changes to the products.

Caught during implementation: the first version flagged 6 images as "broken." Before trusting that result, each URL was independently checked with curl — all 6 returned HTTP 200 with real image bytes. The real bug was in the check itself: it ran before a long, eagerly-loaded image grid had finished downloading. Fixed by polling for img.complete before asserting naturalWidth, then re-verified.

03 What was deliberately left out

Category and brand sidebar filtering were not re-automated on the homepage — they're already covered from the Products page in product.spec.ts, using the identical shared #accordian / .brands_products components. Three more items are documented but intentionally not automated at all:

ItemReason
Hero carousel (arrows, dots)Marketing banner, no business logic, content changes often — brittle for no value
Scroll-to-top buttonCosmetic convenience, zero business impact if broken
Ad-overlay resilienceAlready mitigated structurally by blockAdsBeforeLoad() on every fixture, not by a functional test
